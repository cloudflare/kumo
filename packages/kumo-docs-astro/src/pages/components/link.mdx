## Usage

### Basic Link

  <p>
    The default Link component renders an underlined anchor with primary color styling.
  </p>

```tsx
import { Link } from "@cloudflare/kumo";

export default function Example() {
  return (
    <p>
      Read our <Link href="/docs">documentation</Link> for more details.
    </p>
  );
}
```

### External Links

<p>
  Use the `Link.ExternalIcon` subcomponent to indicate links that open in a new
  tab.
</p>

```tsx
import { Link } from "@cloudflare/kumo";

export default function Example() {
  return (
    <Link
      href="https://cloudflare.com"
      target="_blank"
      rel="noopener noreferrer"
    >
      Visit Cloudflare <Link.ExternalIcon />
    </Link>
  );
}
```

When the effective `target` is `_blank`, Kumo associates the localized
description “Opens in a new tab” with the link. The link's accessible name stays
focused on its destination or purpose. This behavior is based on the explicit
target, not whether the URL is external, and it does not change navigation.

Keep an appropriate visible indication such as `Link.ExternalIcon`. The
accessible description supplements rather than replaces that visual warning.

### New-tab description and localization

Use `KumoLocaleProvider` to translate Kumo-owned description text:

```tsx
<KumoLocaleProvider
  translations={{
    link: { opensInNewTab: "Se abre en una pestaña nueva" },
  }}
>
  <Link href="https://example.com" target="_blank">
    Documentation <Link.ExternalIcon />
  </Link>
</KumoLocaleProvider>
```

Set `announceNewTab={true}` when an application-owned render callback or routing
component chooses `_blank` internally. Set it to `false` when the application
already provides an equivalent description. Opting out removes only Kumo's
description; authored `aria-describedby` and `aria-description` content remains.

```tsx
<span id="custom-new-tab-description" hidden>
  Opens in a separate tab
</span>
<Link
  href="https://example.com"
  target="_blank"
  announceNewTab={false}
  aria-describedby="custom-new-tab-description"
>
  Documentation <Link.ExternalIcon />
</Link>
```

Kumo can infer only props supplied to `Link` or a static `render` element. A
`LinkProvider`, custom component, or render callback that chooses or overrides
the target internally must forward the provided accessibility props and set
`announceNewTab` explicitly when needed. Kumo does not inspect the DOM or invoke
render callbacks to infer navigation behavior.

Descriptions may be announced during ordinary focus navigation, but screen
reader verbosity settings and link-list navigation can omit descriptions. This
feature alone does not guarantee accessibility conformance. W3C
[Technique G201](https://www.w3.org/WAI/WCAG22/Techniques/general/G201) is
advisory and discusses both spoken and visual warnings.

### Framework Integration (LinkProvider)

<p>
  For app-wide router integration, configure a `LinkProvider` at your app root.
  Your wrapper component receives `href` and is responsible for bridging to your
  router's API. This lets engineers use `<Link href="...">` everywhere without
  thinking about routing internals.
</p>

```tsx
import { forwardRef } from "react";
import { LinkProvider } from "@cloudflare/kumo";
import { Link as RouterLink } from "react-router-dom";

// Your app's wrapper maps href to the router's navigation prop
// and handles external URLs with a plain <a>
const AppLink = forwardRef(({ href, to, ...rest }, ref) => {
  const destination = href ?? to;
  const isExternal =
    destination?.startsWith("http") &&
    new URL(destination).origin !== window.location.origin;

  if (isExternal) {
    return <a ref={ref} href={destination} {...rest} />;
  }
  return <RouterLink ref={ref} to={destination} {...rest} />;
});

// Wrap your app once
export function App() {
  return (
    <LinkProvider component={AppLink}>
      {/* All <Link href="..."> calls go through AppLink */}
      <YourApp />
    </LinkProvider>
  );
}
```

### Composition with render prop

<p>
  For exceptional cases where you need direct control over the rendered element,
  use the `render` prop. This bypasses the `LinkProvider` entirely — all other
  props (`href`, `target`, `className`, etc.) are merged onto the provided element
  automatically.
</p>

```tsx
import { Link } from "@cloudflare/kumo";
import { Link as RouterLink } from "react-router-dom";

export default function Example() {
  return (
    <>
      {/* Force a specific router link (bypasses LinkProvider) */}
      <Link render={<RouterLink to="/dashboard" />} variant="inline">
        Dashboard
      </Link>

      {/* Force a plain anchor (bypasses LinkProvider) */}
      <Link render={<a />} href="https://example.com" target="_blank" rel="noopener noreferrer">
        External Site <Link.ExternalIcon />
      </Link>
    </>
  );
}
```

## Design Guidelines

  <div class="space-y-4 text-sm">
    <div>

      ### When to Use Each Variant

      <ul class="ml-4 list-disc space-y-1">
        <li>
          <strong>inline</strong>: Default choice for links within body text
        </li>
        <li>
          <strong>current</strong>: Links inside alerts, banners, or other
          colored containers
        </li>
        <li>
          <strong>plain</strong>: Navigation menus, footers, or where underlines
          are distracting
        </li>
      </ul>
    </div>
    <div>

      ### External Link Indicators

      <ul class="ml-4 list-disc space-y-1">
        <li>Always use `Link.ExternalIcon` for links that open in new tabs</li>
        <li>
          Set `target="_blank"` and `rel="noopener noreferrer"` for security
        </li>
        <li>
          The icon provides a visual cue that users will leave the current site
        </li>
      </ul>
    </div>
    <div>

      ### Framework Integration

      <ul class="ml-4 list-disc space-y-1">
        <li>
          Configure a `LinkProvider` at your app root to integrate with your
          client-side router
        </li>
        <li>
          Your wrapper receives `href` and maps it to your router's
          navigation prop (e.g. React Router's `to`)
        </li>
        <li>
          The wrapper should handle external URLs by rendering a plain
          `&lt;a&gt;` instead of routing them
        </li>
        <li>
          Use the `render` prop as an escape hatch for exceptional cases
          that need direct control over the rendered element
        </li>
        <li>
          The `to` prop is deprecated — use `href` for all link destinations
        </li>
      </ul>
    </div>
    <div>

      ### Accessibility

      <ul class="ml-4 list-disc space-y-1">
        <li>Links are keyboard focusable by default</li>
        <li>
          The external icon has `aria-hidden="true"`; Kumo adds an accessible
          description when the effective target is `_blank`
        </li>
        <li>
          Keep a visible new-tab indication; the screen-reader description does
          not replace it
        </li>
        <li>Ensure sufficient color contrast for all variants</li>
        <li>Use descriptive link text (avoid "click here")</li>
      </ul>
    </div>
  </div>
