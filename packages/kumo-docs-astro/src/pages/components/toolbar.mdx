## Usage

Use `Toolbar` when multiple controls should read as one compact toolbar or
filter card. Use `Toolbar.Button`, `Toolbar.Input`, `Toolbar.InputGroup`,
`Toolbar.Select`, and `Toolbar.Combobox` to opt supported controls into shared
sizing, styling, borders, focus management, and radii.

```tsx
import { InputGroup, Toolbar } from "@cloudflare/kumo";
import { FunnelSimpleIcon, MagnifyingGlassIcon } from "@phosphor-icons/react";

export default function Example() {
  return (
    <Toolbar>
      <Toolbar.InputGroup aria-label="Search DNS records">
        <InputGroup.Addon>
          <MagnifyingGlassIcon />
        </InputGroup.Addon>
        <InputGroup.Input placeholder="Search DNS records" />
      </Toolbar.InputGroup>
      <Toolbar.Button icon={FunnelSimpleIcon} aria-label="Filter" />
    </Toolbar>
  );
}
```

## Behavior

Toolbar item components intentionally own grouped control presentation:

- Every `Toolbar.*` control uses the `base` size by default.
- The Toolbar `size` prop remains available for compatibility but is deprecated; omit it for the base size.
- `Toolbar.Button` always renders with quiet toolbar button styling.
- `Toolbar.InputGroup` passes props directly to `InputGroup` with the resolved toolbar size.
- `Toolbar.Select` replaces only the Select root; use regular `Select.Option`, `Select.Group`, and related children inside it.
- `Toolbar.Combobox` replaces only the Combobox root; use regular `Combobox.TriggerInput`, `Combobox.TriggerValue`, `Combobox.TriggerMultipleWithInput`, content, list, item, and chip components inside it.
- Select and Combobox retain their single/multiple value behavior, popup portals, filtering, and form inputs while joining toolbar arrow-key navigation.
- Adjacent toolbar items share borders and only the outer corners are rounded.
- Direct `Select`, `Combobox`, or other children do not receive toolbar overrides; use the matching `Toolbar.*` root explicitly.

The `size` prop still supports `xs`, `sm`, `base`, and `lg` for compatibility,
but it is deprecated and will be removed in a future major release. Omit it to
use the default `base` size.

### Accessible Labels

Use `aria-label` or `aria-labelledby` for compact controls without visible
labels. A Select trigger and each Combobox trigger still need an accessible
name. For editable inputs, toolbar focus moves only when the caret is already at
the relevant text boundary; while a popup is open, arrow keys navigate its
options instead.

### Toolbar.Select

`Toolbar.Select<Value, Multiple>` supports the regular Select value, items,
loading, form, popup, and single/multiple props. It omits its own `size` and
visible Field layout props because the Toolbar root owns shared sizing and
compact presentation. `className` is applied to the outer grouped item. Use
regular `Select.*` components as children.

### Toolbar.Combobox

`Toolbar.Combobox<Value, Multiple>` supports the regular Combobox root props,
including single and multiple values, filtering, form integration, and disabled
state. It omits its own `size`; the Toolbar root owns shared sizing. `className`
is applied to the outer grouped item. Use regular `Combobox.*` components as
children.

Both wrappers accept `focusableWhenDisabled` to control whether a disabled item
remains in the toolbar's roving focus order.
