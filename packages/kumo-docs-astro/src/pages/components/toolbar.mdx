## Usage

Use `Toolbar` when multiple controls should read as one compact toolbar or
filter card. Render controls through `Toolbar.Control` to opt them into toolbar
sizing, variants, borders, radii, labels, and descriptions.

```tsx
import { Button, Input, Toolbar } from "@cloudflare/kumo";

export default function Example() {
  return (
    <Toolbar size="sm">
      <Toolbar.Control
        render={<Input type="text" placeholder="Search..." aria-label="Search" />}
      />
      <Toolbar.Control render={<Button>Edit</Button>} />
      <Toolbar.Control render={<Button>Add</Button>} />
    </Toolbar>
  );
}
```

</ComponentSection>

## Behavior

`Toolbar.Control` intentionally owns grouped control presentation:

- Control `size` props are ignored and replaced by the toolbar `size`.
- `Button` and `LinkButton` controls render as ghost buttons.
- Labels on controls like `Input`, `Select`, and `Combobox` stay accessible but are visually hidden.
- Descriptions on toolbar controls are ignored to keep the row compact.
- Adjacent `Toolbar.Control` controls share borders and only the outer corners are rounded.
- Direct `Toolbar` children that are not rendered by `Toolbar.Control` do not receive toolbar overrides.

### Sizes

The `size` prop supports `xs`, `sm`, `base`, and `lg`. Every supported child
control rendered by `Toolbar.Control` is locked to the same size.

<ComponentExample demo="ToolbarSizesDemo">
  <ToolbarSizesDemo client:visible />
</ComponentExample>

### Button Actions

Button variants are ignored inside `Toolbar.Control`, so grouped actions remain
visually quiet and consistent.

</ComponentExample>

### Accessible Labels

Controls can still receive `label` props for accessibility. The group hides
those labels visually and ignores descriptions.
