## Experimental

WebMCP is an evolving browser API and is not available across all browsers. `WebMCPForm` renders a native `<form>`, so unsupported browsers retain ordinary form behavior.

Kumo does not expose forms automatically. Applications must explicitly provide a tool name, description, and named controls. Parameter descriptions are recommended; experimental browsers may otherwise derive them from associated labels or ARIA descriptions.

## Usage

```tsx
import { Button, Input, WebMCPForm } from "@cloudflare/kumo";

export default function ProductSearch() {
  return (
    <WebMCPForm
      toolName="search-products"
      toolDescription="Search the product catalog by name"
    >
      <Input
        name="query"
        label="Product name"
        required
        toolParamDescription="Product name or keyword to search for"
      />
      <Button type="submit">Search</Button>
    </WebMCPForm>
  );
}
```

Without `autoSubmit`, an agent can fill the form but the user remains responsible for reviewing and submitting it. Only enable `autoSubmit` for operations where automatic execution is appropriate.

</ComponentSection>

## Supported Controls

This initial release supports declarative parameter descriptions on `Input` and `InputArea`, which render native form controls. Custom controls such as `Select`, `Checkbox`, `Switch`, `Radio`, and `Combobox` are not yet claimed as WebMCP-compatible because browser schema synthesis for hidden and custom controls is still evolving.
